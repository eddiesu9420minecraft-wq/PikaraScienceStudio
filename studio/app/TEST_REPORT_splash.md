# Pikara 統一啟動畫面 — 實測報告（2026-11-27）

共用套件：CreateYourWorld `crates/pikara-splash`（Tauri 2 外掛＋不依賴框架的前端），Create Your World 直接使用，Pikara Science Studio 以 vendored 副本使用（`studio/app/pikara-splash.vendor.json`）。

所有數字都是實際執行測得，沒有估算。原始結果（每次執行一個 JSON，含時間軸與後端步驟）在 CYW 的 `docs/splash-measurements/`，量測工具是 `tools/test/splash-measure.mjs`。

## 量測方法

- 機器：本機 Windows 11（開發機），release 建置（`cargo build --release --features tauri/custom-protocol`）。
- 時間基準：**Windows 回報的行程建立時間**（`Win32_Process.CreationDate`）。外部量測以 CDP（`--remote-debugging-port`）每約 15 ms 輪詢一次頁面狀態；新版另外讀取外掛自己記錄的時間（`timings`，同樣換算成「行程建立後幾毫秒」）。
- **基準版**＝改動前的同一 repo HEAD（Studio：`afd3599`；CYW：`3272dc8`），以相同方式建置與量測。Studio 基準版只加了一個量測用修改：測試資料夾不交給單一實例（否則測試行程會直接把焦點交給使用者正在使用的 Studio 然後結束），不影響啟動時間。
- **Studio** 一律從 Claude 應用程式的 MSIX 容器**外面**啟動（`explorer.exe` 執行 `.cmd`），使用獨立測試資料夾 `PIKARA_STUDIO_DATA=D:\t\sd\…` 與獨立 WebView2 設定檔。從未碰觸正式的 `%APPDATA%\PikaraScienceStudio`。
- **CYW** 從容器內啟動：它的 AppData 寫入會進入容器的私有副本，不會動到使用者真正的 CYW 資料。每次在轉場完成後約 1 秒內結束，背景更新檢查（初始化完成 3 秒後才開始）沒有執行。
- **冷啟動**＝全新的 WebView2 設定檔（Studio 另外是全新的資料夾，資料庫從零建立並升級到 v3）。作業系統的檔案快取**沒有**清除（需要重新開機），所以這是「第一次執行」，不是「開機後第一次」。
- **熱啟動**＝同一資料夾連續再啟動。Studio 每次熱啟動前會用 `tools/test/studio-seed-interrupted.py` 在**測試**資料庫放一個「上次執行中、心跳已過期」的工作，讓「恢復中斷的工作」這一步真的有事可做（兩個版本都一樣）。

## 回歸檢查：啟動畫面永遠不會「沒有回應」

這次開發中實際發生過一次：第一個測試版的啟動畫面頁面很小，會很早呼叫同步指令 `shown`。同步指令在主執行緒上執行，而那時 WebView2 正在用巢狀訊息迴圈建立主視窗。在那裡重入式地顯示／聚焦視窗造成死結，Windows 記錄為 `AppHangB1`，視窗顯示「(沒有回應)」。同時 CSS 的 `display:flex` 蓋過了 `hidden` 屬性，所以空的錯誤面板也顯示出來了。修正方式：外掛的所有指令都改成 async（視窗操作改為排入事件迴圈），`[hidden]` 一律隱藏，狀態快照加上遞增序號（避免舊的狀態覆蓋新的）。

`splash-measure.mjs` 每次執行都會檢查：
- Windows 自己的判定 `Process.Responding`，每 500 ms 取樣；
- 每 250 ms 從啟動畫面頁面做一次 IPC 往返（IPC 一定經過主執行緒）。

只要有任何一次「沒有回應」或 IPC 超過 1 秒，結果就是失敗（exit code 1）。

| 執行 | Windows 取樣（沒有回應／總數） | IPC 最大往返 | 結果 |
|---|---|---|---|
| Studio 慢速（10 秒） | 0 / 27 | 12 ms | 通過 |
| Studio 失敗畫面停留 7 秒（超過 Windows 5 秒判定門檻） | 0 / 21 | 4 ms | 通過 |
| CYW 慢速（9 秒） | 0 / 22 | 57 ms | 通過 |
| CYW 失敗畫面停留 6 秒 | 0 / 14 | 8 ms | 通過 |
| 所有冷／熱啟動（新版） | 0 | ≤ 78 ms | 通過 |
| **反向對照**：同一份程式碼，只把 `shown`／`status` 改回同步指令 | **41 / 43** | — | **失敗（exit 1）** |

反向對照證明這個檢查確實抓得到原本的問題。

（CYW 基準版的 4 次 IPC 探測被誤判為失敗，因為基準版沒有這個外掛、呼叫會出錯；探測已修正為「有回應就算」。這幾次 Windows 取樣全部正常。）
